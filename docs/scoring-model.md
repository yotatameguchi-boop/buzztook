# BuzzTook スコアリングモデル Ver.1

仕様書 §7〜§13 の実装メモ。**このドキュメントはコードと一緒に更新すること。**

## 全体の流れ（仕様書 §8）

```
台本＋投稿条件
  ↓  src/lib/analysis/features.ts
特徴量抽出
  ↓  src/lib/analysis/scoring.ts
生スコア（0-1）
  ↓  ジャンル補正 → アカウント規模補正 → 時期補正
正規化スコア（0-100）
  ↓  src/lib/analysis/percentile.ts
比較母集団の選択 → パーセンタイル変換
  ↓  src/lib/analysis/axes.ts
表示用5軸への集約
  ↓
UI（「上位◯%」を優先表示）
```

各段階のファイルは1責務のみを持つ。スコアを作る場所とパーセンタイルに変換する場所は分離してある（仕様書 §22-1）。

## Ver.1 の実装方針

| 項目 | Ver.1 の実装 | 将来 |
| --- | --- | --- |
| 特徴量抽出 | 表層パターン（辞書ベース）。形態素解析なし | 形態素解析／LLM による構造抽出 |
| スコアリング | ルール + 統計（重み付き線形結合、山型関数） | LightGBM 等の表形式モデル |
| パーセンタイル | 想定した正規分布（平均・標準偏差） | 実データの分布 |
| 類似コンテンツ | 定番構成10件との文字bigramコサイン類似度 | 埋め込みベクトルによる意味的類似度 |
| ジャンル別重み | 手動設定（`GENRE_WEIGHTS`） | 実績データから最適化 |
| 時期補正 | 1.0 固定（未実装） | 投稿予定日時・季節性・トレンド指数 |

**乱数は使っていない。** 同じ台本・同じ条件なら常に同じ結果になる。モデルを差し替えたときの比較可能性のため、この性質は維持すること。

## 10項目の算出根拠

| # | 項目 | 主な特徴量 |
| --- | --- | --- |
| 1 | フック力 | 冒頭のフック種別数、冒頭の長さ、本題までの秒数、冒頭の数字、自己紹介の有無（減点） |
| 2 | 好奇心維持力 | 新情報の投入間隔、伏線、ギャップ表現、列挙マーカー、平均文長 |
| 3 | ターゲット適合性 | ターゲット記述の具体性、ターゲットと台本の語の重なり、ジャンル頻出語、二人称の有無 |
| 4 | 共感性 | 共感表現の密度、コメント誘発の呼びかけ、ターゲットの具体性 |
| 5 | 新規性 | 1 − 参照コーパスとの最大類似度、表現の多様性、具体性。構成が弱い場合は割引 |
| 6 | 構成力 | 5ブロック（HOOK/CONTEXT/DEVELOPMENT/PEAK/ENDING）の検出数、本題までの秒数、締めの位置、展開数、簡潔さ |
| 7 | 情報密度 | 30秒あたりの意味単位数（ジャンル別最適帯からの距離）、想定尺との一致、新情報の回数 |
| 8 | 感情誘発力 | 感情表現の種類数と密度、驚き・ギャップ |
| 9 | 拡散力 | シェア誘発 × 0.50 + コメント誘発 × 0.30 + いいね代理（共感＋感情）× 0.20 |
| 10 | 記憶残存性 | 保存誘発、シリーズ性、新規性。**代理指標のため信頼度は常に LOW** |

拡散力の重み 0.50 / 0.30 / 0.20 は、実績側の `virality_score_raw`（仕様書 §7-9）と同じ配分を台本側の代理指標に適用したもの。実績データが蓄積したら再学習する。

## 信頼度（仕様書 §22-4）

- 台本が60文字未満 → 全項目 LOW
- 記憶残存性 → 常に LOW（代理指標）
- 新規性／共感性／感情誘発力／拡散力 → 実績データがない段階では LOW、同一アカウントの分析が3〜5件を超えると MEDIUM
- フック力・構成力・情報密度など台本のみで測れる項目 → 200文字以上で HIGH

**信頼度が低い項目は、断定的な表現を UI で使わないこと。**

## 改善提案の優先順位（仕様書 §13）

```
Impact = ジャンル別重み ÷ 0.18 × 伸びしろ(1 - score/100) × ルール固有の効果係数
優先順位 = Impact(3/2/1) × Confidence(3/2/1) + Impact の実数値
```

- `DATA_INSIGHT`：抽出済みの特徴量に基づく指摘。根拠となる数値を必ず添える。
- `AI_SUGGESTION`：具体的な書き換え案。データの裏付けがないため、信頼度を1段下げる。

UI 上で両者を混ぜて表示してはいけない（仕様書 §22-2）。

## バージョン管理（仕様書 §22-3）

`src/lib/analysis/version.ts` の以下を、ロジックを変えたら必ず上げる。

- `MODEL_VERSION`  … `features.ts` / `lexicon.ts` を変更したとき
- `SCORING_VERSION` … `scoring.ts` / `percentile.ts` / `recommendations.ts` を変更したとき

全ての分析結果にこの2つを保存しているため、アルゴリズム変更をまたいだ比較でも「何が変わったのか」を追える。バージョンが異なる分析同士を比較すると、バージョン比較画面で警告が出る。

## 既知の限界

1. パーセンタイルの参照分布は実データではなく想定値。**「上位◯%」の絶対値は現時点では目安**であり、同一条件下での相対比較（修正前後の差分）にこそ意味がある。
2. 形態素解析を使っていないため、ターゲット適合性は漢字・カタカナ列の重なりによる近似。
3. 感情・共感は語彙辞書によるマッチのため、皮肉や文脈依存の表現は取りこぼす。
4. 動画側の要素（間・テロップ・カット）は一切考慮していない（Phase 3 の範囲）。
